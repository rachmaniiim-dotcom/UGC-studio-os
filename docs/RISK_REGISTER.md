# Risk and Limitation Register

Status values: **open** (unresolved), **mitigated** (control in place and tested), **accepted** (known and tolerated), **needs validation** (only real-world testing can settle it).

## Integration risks (platforms)

| ID | Risk | Impact | Status | Next step |
|---|---|---|---|---|
| R-01 | **Shoppable scheduling is unproven.** Ordinary TikTok scheduling (TikTok Studio web scheduler, Content Posting API) may not support attaching a TikTok Shop product (yellow basket / keranjang kuning) to a *scheduled* post in TikTok Shop Indonesia, or only for some accounts or only in-app. Product attachment and scheduling are separate capabilities. | Affiliate videos could post without a product link, or need a human at publish time | **needs validation** | Validate on a real eligible account before designing the publisher. The future scheduler must model `canSchedule`, `canAttachProduct` and `canScheduleWithProduct` per account, detected, never assumed. A failed attachment must raise an exception, never post unlinked (spec §5 step 14) |
| R-02 | **Google Flow authentication portability.** Flow is the preferred provider, but: Google often blocks sign-in from embedded or automated browsers; Chrome on Windows is rolling out device-bound session credentials that tie Google session cookies to the device; sessions may be invalidated on IP/OS/device change (laptop → VPS). A Cookie-Editor export of Google cookies may not work in Electron and is unlikely to work on a Linux server. | Unattended generation may be impossible via cookies | **needs validation** | Dedicated Flow spike after Gate 2. Keep the provider interface replaceable. **Possible authorized fallback:** Google's official Veo access through the Gemini API or Vertex AI (paid per use, API key or service account, no browser session). Pricing and terms must be checked when the fallback is considered |
| R-03 | **Unresolved authorization constraint. Kalodata's Terms of Service restrict automation.** The owner reports that section 4.1.8 of the published terms restricts automated scripts that collect information from or interact with the service. **Material integration risk** (updated 2026-10-22) | Research automation would breach the terms; account loss | **blocking for automation** | No Kalodata automation (scraping, scripted interaction, scheduled extraction) without written permission from Kalodata or an authorized alternative (official API, data licence). Any Gate 2 scope touching Kalodata needs an explicit owner decision |
| R-03b | **Unresolved authorization constraint. Kalodata terms restrict data use beyond automation** (read 2026-10-22, terms dated 2026-04-16): §14.6 forbids using Kalodata data in AI/ML/LLM systems, including via prompts or APIs, without written consent; §14.3–14.5 require an enterprise agreement for system integration and persistent datasets | The research → AI generation pipeline as specified would breach the terms | **blocking for research module** | Owner decision: written permission from Kalowave, Charm Enterprise Package, or another data source. Kalodata data never enters Claude conversations (`docs/gate-2/GATE2_READINESS.md` §3) |
| R-23 | **First-launch key window (Windows).** Chromium writes a new profile's DPAPI-wrapped key to `Local State` ~10.3 s after first launch; a crash before that makes everything encrypted in that window unrecoverable (snapshots and Chromium's cookie DB) | Session data lost (fails closed, no leak) | **mitigated** | Imports are refused (`protected_key_not_ready`) until the key is on disk; tested |
| R-24 | **Security-check coverage.** Values under 8 bytes, encodings other than raw/URL, compressed files (git history), files over 256 MB and locked files are not searched; only given folders are scanned | A leak could go unreported | **accepted** | Run with `--scan` on any folder an export may have touched; history protected by the pre-commit hook (R-25) |
| R-25 | **Git hook bypass.** `git commit --no-verify` skips the pre-commit scan; nothing scans on the server side | Secrets could be committed deliberately or by mistake | **open** | Add a CI/server-side scan when CI exists |
| R-26 | **Site-written storage is plaintext at rest.** Chromium encrypts cookies only. Gate 2 found script-readable cookie values (including a Kalodata session cookie) copied by the site into Local Storage, IndexedDB, HTTP cache and TransportSecurity | Secondary exposure of sensitive data on disk | **open** | Treated as sensitive (not harmless). Gate 3: clear the HTTP cache on exit (Q6); recommend full-disk encryption; `security-check` keeps reporting them |
| R-27 | **Main-process requests can't authenticate to a proxy** (Electron 44, measured): `session.fetch` gets the 407, and no `login` event fires | Automated probes fail through authenticated proxies (they fail closed, never direct) | **accepted** | Real platforms use owner-confirmed status; every authenticated proxied action comes from a window (Test Proxy does) |
| R-28 | **Proxy IP change vs imported session** (R-05 applied): cookies exported on the home IP are then used from the proxy IP | Platform security checks, logout | **needs validation** | Prefer "Log in here" through the bundle's proxy (Q7), or export from a browser already using that proxy |
| R-29 | **Pasted Cookie-Editor JSON crosses the renderer once** (B1). The textarea is replaced on submit and the text never enters state or storage, but JS strings can't be zeroed and the OS clipboard keeps the copy | Brief in-memory exposure; clipboard copy | **accepted** | UI tells the owner to overwrite the clipboard; file import remains available (main process reads the file) |
| R-30 | **Proxy host/port and observed IP in SQLite** (non-secret, but they link accounts) | Account linkage if `ugc.db` is read | **accepted** | Kept out of logs; `ugc.db` ignored by Git and blocked by the pre-commit hook; data folder outside OneDrive |
| R-31 | **Q6 (clear the HTTP cache on exit) not yet implemented** | Plaintext site cache at rest (R-26) | **open** | Next hardening item |
| R-32 | **Google Flow automation feasibility** (Gate 4): no official API; reCAPTCHA Enterprise on the site; the help center treats proxies/VPNs as an "Unusual activity" cause; imported Google sessions may be refused in Electron | Automation may be blocked or put the Google account at risk | **needs validation** | Owner-run manual test first (`docs/gate-4/FLOW_FEASIBILITY.md` §6); no real-Flow automation until approved; never solve or evade challenges |
| R-33 | **Flow download exception**: the only place a partition accepts downloads | A malicious or unexpected file could be saved | **mitigated** | Google Flow sessions only; Google domains; MP4 MIME/extension; 512 MB cap; MP4 signature check after download; partial and invalid files deleted; tested |
| R-34 | **Owner-entered research metrics** (Gate 5): numbers copied by hand or from CSV can be mistyped, display-rounded or stale; links are not verified against TikTok (verifying would be automated access) | Wrong outlier calls | **mitigated** | Rounded/stale/incomplete data lowers confidence and is flagged; inconsistent metrics block an outlier verdict; small baselines are "unverified", never scored; every verdict has a plain explanation |
| R-35 | **No authorized automated TikTok research source** (ToS §5; Research API academic-only; Display API own videos only) | Daily research needs the owner until a licensed source exists | **open** | Provider interface refuses sources without a recorded automated-retrieval authorization (tested); add a licensed provider once its terms are confirmed (D21 Q5) |
| R-22 | **Concurrent sessions:** using the same Kalodata session in Chrome and the app may be detected as sharing (§3.4) or a new device | Forced logout, account flag | **needs validation** | Gate 2 procedure: stop using Chrome during the test, stop on any notice |
| R-04 | TikTok / TikTok Shop UI automation may breach terms; official APIs require app review | Account risk; brittle automation | **open** | Prefer official APIs where they exist; validate per capability |
| R-05 | Device/IP-bound sessions: platforms may reject imported sessions on a different machine, OS or IP | Laptop → VPS migration may need re-login on the server | **needs validation** | Per-platform experiment; never bypass checks |

## Technical findings from Gate 1

| ID | Finding | Status | Consequence / mitigation |
|---|---|---|---|
| R-10 | **Session cookies are lost on restart.** Cookies without `expirationDate` imported into a `persist:` partition are gone after the app restarts (tested, Electron 44.9.3) | **mitigated** | C1 (2026-10-22): the live jar's session cookies are re-sealed on every change (rotation, deletion) with `safeStorage` (DPAPI on Windows) and restored at startup, with revision checks; tested with crashes (`docs/gate-2/PRE_GATE2_HARDENING_REPORT.md`). Gate 3 vault replaces the storage |
| R-11 | **Partitioned (CHIPS) cookies can't be loaded.** Electron 44's `cookies.set()` has no partition-key field | **mitigated** | The adapter skips them with `unsupported_partitioned` and reports it; it never stores them unpartitioned. Re-check on Electron upgrades |
| R-12 | **Cookie-only import is insufficient for sites needing non-cookie state** (localStorage, IndexedDB, device tokens). Shown with the synthetic `/strict` page | **accepted** | Interactive login in the isolated partition works and persists across restart (tested). Real sites: Gate 2 finding |
| R-13 | **Without the fuse, cookie values sit in plaintext** in the partition's `Cookies` SQLite database (tested) | **mitigated in code; packaging pending** | Import refuses to run unless the `EnableCookieEncryption` fuse is on (explicit synthetic-only override for tests). Production fuse set defined in `apps/desktop/scripts/fuse-config.mjs`; must be applied and verified when packaging exists |
| R-14 | **On headless Linux, Chromium's cookie encryption is obfuscation only.** With the fuse on, values were encrypted (`v10` prefix), but with no OS keyring Chromium uses a built-in fallback key. `safeStorage` reported `isEncryptionAvailable: false`, backend `basic_text` | **accepted for the container; Windows verified** | Verified on Windows 2026-10-22: `v10` is AES-256-GCM with a DPAPI-wrapped key in `Local State`, decrypted only as the current user. The session-restore prototype refuses `basic_text`. The future Linux worker must not rely on Chromium/Electron encryption; use systemd-creds, KMS or Vault |
| R-15 | **Chromium refuses to run as root without `--no-sandbox`.** In the container the suite runs as an unprivileged user under Xvfb, so the sandbox stays on | **mitigated** | `scripts/e2e-container.sh`. The app never passes `--no-sandbox` |
| R-16 | Playwright drives Electron through `--inspect` and remote debugging, which the production fuse set disables | **open** | Packaged-build tests need another approach (e.g. fuses applied after e2e, or a test-only packaged variant). Not solved in Gate 1 |
| R-17 | The forged-IPC test calls Electron's private `ipcMain._invokeHandlers` | **accepted** | Test-only; may break on Electron upgrades |
| R-18 | Reading the fuse wire scans the ~229 MB Electron binary on first import | **open** | Not measured. Cache is per process. Consider reading once at startup or checking at packaging time |
| R-19 | Same-user malware can read anything the app can (DPAPI and Chromium encryption protect against other users and offline theft, not processes running as the same user) | **accepted** | Documented; minimize plaintext lifetime |
| R-20 | **Session snapshot rollback (residual after C1).** Rotation, deletion and partial rollback are handled (C1). Remaining: restoring all three copies (snapshot, revision record, metadata) from one earlier moment is not detected (no hardware monotonic counter); decrypted JSON is an unzeroable JS string; a change within ≤250 ms of a crash may be lost. Original Gate 1 limit, for history: records were sealed at import only (cookies the site sets or rotates later are not captured); no anti-rollback for a profile's own older record; decrypted JSON is an unzeroable JS string; restoring extends a login the site meant to end with the browser | **accepted for Gate 1** | Gate 3 vault: refresh from the live jar, versioning/anti-rollback, key rotation. Real-site behaviour is a Gate 2+ finding |
| R-21 | **Native-dialog test relies on Windows common-dialog control IDs** (1148/1/2), driven by UI Automation plus `WM_SETTEXT`/`BM_CLICK` because build 26300 exposes them without UIA patterns | **accepted** | Opt-in test (`UGC_E2E_NATIVE_DIALOG=1`); re-check on Windows updates |
